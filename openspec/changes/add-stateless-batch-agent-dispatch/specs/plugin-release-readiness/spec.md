## MODIFIED Requirements

### Requirement: Default release smoke costs no Claude model usage
The default release smoke SHALL verify the enabled matching HarnessDock Plugin,
exactly nine `$codex-harnessdock:*` Skills, exactly nine typed MCP tools
including singular `spawn_agent` and `dispatch_agents`, the subsequent MCP
generation, compatibility shells, and isolated `list_agents`/fresh
zero-argument `list_harnesses` calls. It SHALL keep the discovered MCP catalog
within the existing 4,500-character serialized bound without deleting
decision-bearing route, authority, preflight, cancellation, or row-outcome
semantics. It SHALL not start a Codex, Claude, Pi, OpenCode, or provider model
turn; Harness listing retains its existing dormant-service behavior.

#### Scenario: Matching dispatch generation is installed
- **WHEN** the operator runs zero-model release smoke
- **THEN** it proves the nine-tool/Skill surface and isolated lifecycle wiring
  without model usage

#### Scenario: Catalog exceeds its current bound
- **WHEN** the ninth schema causes serialized discovery to exceed 4,500
  characters
- **THEN** release fails until duplicated guidance is compacted without
  weakening safety; the bound is not silently raised

#### Scenario: Installed snapshot still exposes eight tools
- **WHEN** source expects the dispatch generation
- **THEN** smoke fails before lifecycle execution and requires local refresh/new
  Codex task
